# Foundry BYO-VNet (Bring Your Own Network)

Terraform configuration that provisions an **Azure AI Foundry** account with a
**Standard Agent Service** setup inside a customer-managed (bring-your-own)
virtual network. All data-plane resources are reached over **private endpoints**
with public network access disabled, and a Bastion-fronted jumpbox VM is included
for private validation.

## Architecture

This configuration deploys the following into a single new resource group:

| Component | Resource | Notes |
| --- | --- | --- |
| AI Foundry account | `Azure/avm-ptn-aiml-ai-foundry/azurerm` | Private-only, with AI Agent Service enabled |
| Model deployment | `gpt-4.1` (OpenAI) | `GlobalStandard`, capacity 1 |
| AI Search | `azapi` `Microsoft.Search/searchServices` | Standard SKU + private endpoint |
| Cosmos DB | module | Agent thread storage (private) |
| Storage Account | module | Project storage (private) |
| Key Vault | module | Secrets (private) |
| Log Analytics | `azurerm_log_analytics_workspace` | Diagnostic settings target |
| Bastion + Jumpbox VM | `avm-res-network-bastionhost` + `avm-res-compute-virtualmachine` | Windows Server 2022, private validation host |

### Networking

Two VNets are created in the Foundry resource group:

- **Private-endpoints VNet** (`10.2.0.0/16`)
  - `snet-private-endpoints` — all private endpoints
  - `AzureBastionSubnet` — Bastion host
  - `snet-vm` — jumpbox VM
- **Agent-services VNet** (`172.17.0.0/16`)
  - `snet-agent-services` — delegated to `Microsoft.App/environments` for agent
    compute injection

Private DNS zones are created for blob, file, Key Vault, Cosmos DB, AI Search,
OpenAI, Cognitive Services, and AI services, and are linked to the
private-endpoints VNet.

> **Important — address space constraint:** The AI Agent platform rejects any
> VNet whose address space overlaps the reserved `10.0.0.0/8` range. Keep the
> delegated agent subnet in a VNet with **no `10.x` overlap** (this config uses
> `172.17.0.0/16`). See the inline note in [`foundry.tf`](foundry.tf) for details.

## Prerequisites

- [Terraform](https://developer.hashicorp.com/terraform/install) `>= 1.9, < 2.0`
- [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli) (authenticated via `az login`)
- An Azure subscription with sufficient quota for:
  - Cognitive Services / Azure OpenAI (`gpt-4.1`)
  - Standard AI Search
  - The selected VM SKU (`Standard_D4s_v3`)
- Permissions to create resource groups, role assignments, and private endpoints

## Configuration

All input is provided through a `terraform.tfvars` file (gitignored). Copy the
example and fill in your values:

```bash
cp terraform.tfvars.example terraform.tfvars
```

### Input variables

| Variable | Type | Required | Description |
| --- | --- | --- | --- |
| `subscription_id` | `string` | Yes | Azure subscription ID where Foundry is provisioned |
| `location` | `string` | Yes | Azure region (e.g. `southeastasia`) |
| `foundry_rg_name` | `string` | Yes | Name of the new resource group |
| `pep_vnet_name` | `string` | Yes | Name of the private-endpoints VNet |
| `pep_subnet_name` | `string` | Yes | Name of the private-endpoints subnet |
| `agent_svc_vnet_name` | `string` | Yes | Name of the agent-services VNet |
| `agent_svc_subnet_name` | `string` | Yes | Name of the agent-services subnet |
| `base_name` | `string` | No (`byor`) | Short suffix used by the naming module |
| `pep_vnet_subnet_cidrs` | `object` | Yes | CIDRs for `private_endpoints`, `bastion`, `vm` subnets |
| `agent_vnet_subnet_cidrs` | `object` | Yes | CIDR for `agent_services` subnet |
| `tags` | `map(string)` | No | Tags applied to created resources |

## Usage

```bash
# Initialize providers and modules
terraform init

# Review the plan
terraform plan

# Apply
terraform apply
```

### Connecting to the jumpbox

The jumpbox VM admin password is generated by Terraform and marked sensitive.
Retrieve it after apply:

```bash
terraform output -raw vm_admin_password
```

Connect through Azure Bastion (username `azureadmin`), then use the VM to
validate that the Foundry endpoints resolve to private IPs:

```bash
nslookup <foundry-name>.cognitiveservices.azure.com
nslookup <foundry-name>.openai.azure.com
nslookup <foundry-name>.services.ai.azure.com
```

A correct result shows a `privatelink.*` CNAME resolving to a private
(`10.x` / `172.x`) IP from the private-endpoints subnet.

## Cleanup

```bash
terraform destroy
```

> The configuration includes a destroy-time purge of the soft-deleted Cognitive
> Services account (with a cooldown) so the service association link on the
> delegated agent subnet is released cleanly. Destroy may take several minutes.

## Notes

- `public_network_access_enabled = false` on the Foundry account — all access is
  via private endpoints from inside (or peered to) the VNet.
- State files (`*.tfstate`), `terraform.tfvars`, the `backup/` folder, and logs
  are excluded from version control. The generated VM password lives only in
  local state.
